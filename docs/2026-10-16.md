# API thay đổi ngày 2026-10-16

Tài liệu này tổng hợp các API có thay đổi trong những thay đổi **chưa commit** tại ngày 2026-10-16. Các API không được liệt kê bên dưới không có thay đổi hợp đồng được phát hiện trong phần diff hiện tại.

## Tóm tắt

- Thêm luồng đăng ký Owner có trạng thái chờ Admin duyệt.
- Thêm API Admin xem, duyệt và từ chối hồ sơ đăng ký Owner.
- Thay đổi response đăng ký Customer, response hồ sơ hiện tại và cách xử lý một số trường hợp khóa/mở khóa tài khoản.
- Gỡ endpoint gán permission cho role; API dùng role `Admin`, `Owner`, `Customer` thay vì permission chi tiết.

Các endpoint yêu cầu đăng nhập nhận JWT qua header:

Gửi access token nhận được từ API đăng nhập trong header `Authorization` với scheme `Bearer`.

## API đăng ký và hồ sơ tài khoản

### `POST /api/users/register` — thay đổi response thành công

Đăng ký tài khoản Customer. Request giữ nguyên:

```json
{
  "username": "customer01",
  "password": "password123",
  "fullName": "Nguyen Van A",
  "phone": "0901234567",
  "address": "Ha Noi",
  "email": "customer@example.com",
  "createBy": null
}
```

- Thành công: `200 OK`, trả `{ "message": "Đăng ký tài khoản thành công." }`.
- Thất bại: `400 Bad Request`.
- Thay đổi so với response cũ: không trả lại object request, đặc biệt không echo trường mật khẩu.

### `POST /api/users/register-owner` — mới

Đăng ký tài khoản Owner kèm thông tin tài khoản ngân hàng. Không yêu cầu đăng nhập.

Request:

```json
{
  "username": "hotel.owner",
  "password": "password123",
  "fullName": "Nguyen Van A",
  "phone": "0901234567",
  "address": "1 Duong Mau, Ha Noi",
  "email": "owner@example.com",
  "bankName": "Vietcombank",
  "bankAccountNumber": "0123456789",
  "bankAccountHolder": "NGUYEN VAN A",
  "bankBranch": "Ha Noi"
}
```

Các trường trên là bắt buộc, ngoại trừ `bankBranch`. Username tối đa 100 ký tự; mật khẩu từ 8 đến 100 ký tự; phone và email phải hợp lệ. Giới hạn độ dài các trường khác được kiểm tra bằng validation trên request model.

- Đăng ký thành công: `202 Accepted`, tài khoản ở trạng thái chờ duyệt và chưa đăng nhập được.
- Username hoặc email đã tồn tại: `409 Conflict`.
- Dữ liệu không hợp lệ: `400 Bad Request`.
- Role `Owner` chưa được cấu hình trong DB: lỗi cấu hình phía server.

**Yêu cầu schema:** trước khi bật endpoint, áp dụng [owner-registration.sql](./owner-registration.sql) để thêm các cột trạng thái và thông tin duyệt vào `UserProfile`.

### `GET /api/users/me` — thay đổi response

Yêu cầu đăng nhập. Trả thông tin cơ bản và role của người dùng từ token; không nhận ID người dùng từ client.

Response `200 OK`:

```json
{
  "fullName": "Nguyen Van A",
  "roleId": "00000000-0000-0000-0000-000000000001",
  "roleName": "Customer"
}
```

Response trước đây có danh sách `permissions`; trường này được bỏ do API chuyển sang kiểm soát truy cập bằng role. Token không có user ID hoặc role ID trả `401 Unauthorized`.

## API Admin quản lý hồ sơ Owner

Các endpoint trong mục này yêu cầu role `Admin`.

### `GET /api/users/admin/owner-registrations` — mới

Liệt kê hồ sơ đăng ký Owner, có thông tin tài khoản ngân hàng mặc định nếu tìm thấy.

Query:

| Tên | Kiểu | Mặc định | Mô tả |
|---|---|---:|---|
| `status` | integer | Không lọc | `0` chờ duyệt, `1` đã duyệt, `2` bị từ chối |
| `keyword` | string | Không lọc | Tìm theo username, tên, email hoặc số điện thoại |
| `page` | integer | `1` | Số trang, bắt đầu từ `1` |
| `pageSize` | integer | `20` | Số dòng mỗi trang, tối đa `100` |

`page <= 0`, `pageSize <= 0`, `pageSize > 100` hoặc `status` không thuộc `0`, `1`, `2` trả `400 Bad Request`.

Response `200 OK`:

```json
{
  "data": [
    {
      "userId": "00000000-0000-0000-0000-000000000002",
      "username": "hotel.owner",
      "fullName": "Nguyen Van A",
      "email": "owner@example.com",
      "phone": "0901234567",
      "address": "1 Duong Mau, Ha Noi",
      "approvalStatus": 0,
      "reviewNote": null,
      "reviewedAt": null,
      "createdAt": "2026-10-16T09:00:00Z",
      "bankAccount": {
        "bankName": "Vietcombank",
        "accountNumber": "0123456789",
        "accountHolder": "NGUYEN VAN A",
        "branch": "Ha Noi"
      }
    }
  ],
  "totalRow": 1,
  "totalPage": 1,
  "page": 1,
  "pageSize": 20
}
```

### `PUT /api/users/admin/owner-registrations/{userId}/approve` — mới

Duyệt hồ sơ Owner đang chờ. Khi duyệt, tài khoản được bật để đăng nhập và email thông báo được gửi vào hàng đợi `register_email_queue`.

- Thành công: `200 OK` với message xác nhận.
- Hồ sơ không tồn tại hoặc không còn chờ duyệt: `409 Conflict`.
- Token không hợp lệ/thiếu role Admin: `401 Unauthorized` / `403 Forbidden`.

Không cần request body.

### `PUT /api/users/admin/owner-registrations/{userId}/reject` — mới

Từ chối hồ sơ Owner đang chờ, giữ tài khoản không thể đăng nhập và gửi email kèm lý do vào hàng đợi `register_email_queue`.

Request:

```json
{
  "reason": "Thông tin tài khoản ngân hàng chưa hợp lệ"
}
```

`reason` là bắt buộc, tối đa 500 ký tự. Lý do rỗng trả `400 Bad Request`; hồ sơ không tồn tại hoặc đã được xử lý trả `409 Conflict`; thành công trả `200 OK`.

## API Admin khóa/mở khóa tài khoản

### `PUT /api/users/admin/{userId}/status` — thay đổi hành vi lỗi

Yêu cầu role `Admin`. Request hiện tại:

```json
{ "isDel": 0 }
```

`isDel = 0` mở khóa; `isDel = 1` khóa.

- Thành công: `200 OK` với message tương ứng.
- Admin không thể tự khóa tài khoản đang đăng nhập: `400 Bad Request`.
- Tài khoản không tồn tại hoặc đang cố mở khóa Owner chưa được duyệt: `400 Bad Request`.

Thay đổi so với hành vi cũ: trường hợp không tìm thấy tài khoản trước đây trả `404 Not Found`, hiện trả `400 Bad Request`; đồng thời không cho mở khóa Owner chưa được duyệt.

## API đã gỡ

### `POST /api/users/role-permissions` — đã xóa

Endpoint cũ cho phép Admin gán `Resource`/`Permission` vào role đã bị gỡ. Các bảng quyền chi tiết và `HasPermissionAttribute` không còn được API dùng. Role vẫn được kiểm tra trên các endpoint hiện hành bằng `[Authorize(Roles = "...")]`.

Sau khi client bỏ gọi endpoint này, request tới route cũ sẽ không còn được xử lý và trả `404 Not Found`.
